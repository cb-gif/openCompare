# 质量与验收规范

质量门槛对应 [plan.md](plan.md) 节点。本文中的性能数字是初始目标，不能作为已测结果或下载承诺。

## 完成定义

功能节点只有同时满足以下条件才勾选：

1. 需求范围和失败行为实现，受影响调用方、类型、UI、配置与文档同步。
2. 非平凡逻辑有能证明行为的测试；文件写入的失败保护有覆盖。
3. 对应自动检查通过；涉及桌面、编码或文件系统的变化在相关平台验收。
4. 证据注明提交或工作树范围、环境、命令/步骤、实际结果、限制；缺少平台时记录待验收。
5. 未完成部分有独立节点，不以“后续完善”隐藏在已完成项目中。

文档节点以文档与校验产物验收；原型 BASE 节点只证明历史基线。不能把它们计入新桌面功能完成率。

## 分层检查

| 层 | 必查行为 | 检查方式 |
| --- | --- | --- |
| compare-core | 应用差异重建目标、撤销恢复、过期结果拒绝、Unicode 边界 | Rust 单元测试、共享样本 |
| compare-fs | 编码/仅格式转换、失败不破坏原文件、类型与根路径约束、外部变化 | 临时目录集成测试；真实平台补充 |
| compare-app | 身份/写入键、正文与格式保存交错、复制冻结及终态清理、配置迁移 | 服务测试与故障注入 |
| DTO/IPC | 类型生成无漂移、无效输入拒绝、任务及修订绑定 | 生成差异检查、边界集成测试 |
| React/编辑器 | 正文/目标格式 dirty、undo、冻结期间变更入口、选择与虚拟列表 | Vitest + 必要的组件/浏览器测试 |
| 桌面与安装 | WebView/CSP/worker、IME、启动模式、Git 等待、文件权限、安装升级 | Windows/macOS 原生应用与安装包验收 |

只对改动相关的行为增加测试，不以覆盖率数字替代关键路径验证。纯文案和低影响样式调整不强制新增单元测试，检查链接或视觉即可。

## 共享样本

样本应可公开、体积受控、注明预期语义，不使用真实私人文件。大样本由固定参数脚本生成，避免把大文件提交到仓库。

| 样本组 | 必须覆盖 |
| --- | --- |
| 文本 | 空、仅换行、无末尾换行、LF/CRLF/混合、插入删除、重复行、整文件不同 |
| 字符 | 中文、emoji、组合字符、制表符、长行、不可编码字符、无效字节 |
| 格式 | UTF-8 有/无 BOM、UTF-16LE/BE、GBK、仅 BOM/编码/换行变更、转换失败 |
| 目录 | 同名异类型、深路径、大小写冲突、Unicode 等价名称、权限拒绝、扫描中删除 |
| 文件操作 | 只读、被占用、磁盘满/写失败、源/目标变化、目标晚出现、链接/越界、取消与部分成功 |
| 状态 | 保存中继续编辑/改格式/关闭、复制启动后输入与重开、冻结清理、旧回执晚到、文件别名、损坏/未来版本配置 |

链接创建权限不足只能记作跳过，不算该平台用例通过。故障注入不能代替所有真实操作系统行为，但可稳定覆盖难以复现的失败分支。

## 关键协议验收

以下是待执行验收条件，不是已有通过结果。

| 归属 | 输入或时序 | 必须观察的结果 |
| --- | --- | --- |
| FND-02、FND-04 | 正文不变，仅切换 UTF-8 BOM；仅 GBK 转 UTF-8；仅 LF/CRLF 转换 | dirty 为真，输出字节符合目标格式，成功后基线更新；正文与目标格式均不变才走原字节复用 |
| FND-02、FND-04 | 保存捕获格式 A 后改成 B，再收到 A 的成功回执 | 磁盘与保存基线是 A，当前目标仍是 B 且 dirty；迟到或错误世代回执不能覆盖当前正文/格式 |
| FND-02、FND-04、VAL-01 | 不可编码字符转换到 GBK、非法 BOM/编码组合、写入失败；正文或格式撤销回基线 | 失败保留当前正文和目标格式、原磁盘字节与旧基线；只有正文与格式都恢复才清除 dirty |
| OPS-01、VAL-01 | 目标起初 clean；预留后冻结确认前输入或提交 IME | 最新状态纳入冻结确认，变 dirty 时整批不写且解除保护，无字符丢失 |
| OPS-01、OPS-02、VAL-01 | 确认冻结后键入/粘贴/改格式/撤销/接收块；关闭并重新打开目标或别名 | 所有变更入口受限，重开只显示保护状态；不能生成可被后续重载覆盖的新输入 |
| OPS-02、VAL-01 | 注入标记或世代不匹配、迟到回执、取消、部分失败、重载失败、窗口消失 | 不匹配时保留 model/格式报冲突；终态后释放全部保护，无已提交结果丢失；取消请求发出但写入未停时不能提前解冻 |
| GIT-01 | 普通窗口有正文/格式未保存，调用 difftool；再连续调用不同文件对 | 专用进程只读磁盘，原窗口完全保留；每次 CLI 只等自身会话，不因转交/其他窗口退出而返回 |
| GIT-01 | 实际 Git 调用下延迟读取临时文件，明确完成、关闭/取消、启动/读取失败、进程异常退出 | 输入加载成功才允许完成；临时输入在读取/句柄释放前调用方仍处于等待。声明并使用退出状态配置，完成 0、无错误取消 1、错误 2，进程退出后无后台读取 |

FND-02 的状态/回执用例先验证控制器协议，FND-04 再验证真实编码与磁盘字节；不得以 mock 成功代替实际格式转换通过。VAL-01 在接入完整编辑和复制流程后复验这些约束。

## 原生验收场景

FND-03 是 M0 的编辑器可行性门槛，必须先完成以下最小集合：

- Windows/macOS 各记录至少一种中文 IME、系统/WebView/输入法版本；在双侧编辑中验证组合提交、取消、光标/焦点切换，不重复插入或丢失组合字符。
- 使用最终将采用的 CSP 和本地资源路径启动离线 Release 应用，直接确认 Monaco worker 创建及差异工作正常；不得关闭 CSP、借用 Vite 开发服务或 CDN 来使验证通过。
- 对超长单行、重复行、密集差异及全量不同设置期限/体积上限，观察明确的只读、截断展示或拒绝提示，UI 可取消且不误报相同；截断展示不能覆盖完整文件。
- 输出下节规定的编辑上限、内存与冷/热启动初步预算。此阶段不承担完整无障碍、安装升级或目录性能验收。

每个发布候选至少覆盖：启动 → 打开目录 → 过滤 → 双击文件 → 编辑/块接收 → 撤销/重做 → 保存 → 返回目录刷新；另测预览覆盖、取消与部分失败、退出未保存、重启恢复会话、Git 调用。

UX-02 完成 Windows/macOS 的完整中文输入法组合/候选窗、快捷键、焦点、屏幕阅读标签、高 DPI 与多显示器验收。REL-01/REL-02 负责安装、签名、升级等发布检查。macOS arm64 和 x64 是不同发布目标，M0 在已明确记录的 Windows/macOS 环境通过不能替代三目标正式发布验收。

Playwright 浏览器测试可验证前端流程和截图，但不能证明 Tauri 命令、WebView、系统对话框与安装程序正常。原生自动化驱动是否适用由 FND-07 实测决定；不可自动化的项目使用可复现手工步骤并记录结果。

## 性能基线与预算

Release 构建固定样本，记录系统/CPU/内存/架构、WebView、依赖版本、文件大小、变化分布、冷热缓存。交互采集足够事件报告 p50/p95；启动和批处理至少重复 5 次，报告中位数与最差值，保留原始数据。

| 场景 | 初始目标或必须记录的数据 |
| --- | --- |
| 每侧 1 MiB 普通源码 | 输入反馈 p95 ≤ 50 ms，滚动帧耗时 p95 ≤ 33 ms |
| 每侧约 10 MiB / 10 万行 | 首个可用结果、完整结果、跳转/滚动、峰值内存；允许明确只读降级 |
| 超长行、重复行、全量不同 | 计算期限、降级原因、取消可达性，不能冻结界面 |
| 10 万项目录 | 首批/完成时间、可见 DOM 数、内存与取消停止延迟 |
| 取消 | UI 反馈目标 ≤ 100 ms；后台停止延迟单独测量 |
| 空闲与生命周期 | 冷/热启动、打开/关闭 20 次、未来 10 标签场景；统计 Rust 与 WebView 相关进程 |

预算归属：

- FND-03 在 M0 测可用 Windows/macOS 环境的 1 MiB 交互、10 MiB 探针、病理文本、单会话进程总峰值内存和冷/热启动。产出可编辑字节/行长上限、降级规则、内存与启动初步预算；每个值附实际数据、环境、构建、选择理由与未验范围，不填写推测的通过结果。
- TXT-06 将这些上限和降级落实到文件打开；VAL-02 用完整产品的文本、十万项目录、取消及反复开关等负载验证或修订。后续 10 标签场景由 SES-01 验收，不能作为 M0 的前置。
- UX-02 负责完整可访问性，REL-01/REL-02 负责安装升级，均不挤入 FND-03。预算变化同步本规范与对应证据，保留原失败样本与调整理由。

上表数字仅为初始测量目标，目前没有新桌面预算实测值。不得通过删掉失败样本使门槛“通过”。现有 1,306 ms 仅是历史稀疏变化 Debug CLI 数据，见 [validation.md](validation.md)。

## 证据格式

validation.md 按验收对象和日期记录结果，较大附件放对应任务的测试产物中。只保留结论、通过/失败/未验证状态、必要证据与限制，不记录对话经过、操作流水或中断重试叙述；失败结论和影响仍需保留，不能清理成“全部通过”。

命令、环境和最小复现步骤用于解释结果，不用于复述工作过程。同一对象的重复检查可合并，范围或环境不同的结果分开标明；普通沟通、命名调整和文案修改无需各写一轮日志，不把上一环境结果复制成新验证。

```text
任务：TXT-03
范围：提交 SHA / 未提交文件范围
环境：系统、CPU 架构、工具链、构建模式
检查：命令或原生操作步骤、输入样本
结果：通过 / 失败 / 跳过，各项实际观察
证据：测试名、日志或截图路径（需脱敏）
限制：未验平台、竞争窗口、人工检查项
```

性能日志不含正文，截图和路径必须检查是否有敏感信息。发布候选失败的节点保持未勾选；修复后保留原失败与复验结果。
