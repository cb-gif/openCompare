# 架构、工程与产品审查结论

审查日期：2026-11-06。范围为当前源码、原型验证记录和目标桌面产品设计；不构成完整代码安全审计。

## 总体结论

采用 Rust + Tauri 2 + TypeScript，界面使用 React + Vite，组件使用 Tailwind CSS + shadcn/ui，编辑器优先验证 Monaco。保留 Rust 核心与文件操作实现，重建桌面交互层。主要风险是文档保真、比较语义一致性、文件操作安全和双平台交付；增加界面功能不能替代这些验证。

## 审查结果与处理

| 视角 | 优先级 | 问题与证据 | 结论与任务 |
| --- | --- | --- | --- |
| 架构 | P0 | Monaco 对齐与 Rust hunks 可能来自不同算法，原型还有忽略大小写、行尾空白规则 | 一个交互动作使用同一份带修订的结果；兼容规则必须用共享样本验收。FND-03、TXT-04 |
| 架构 | P0 | 全量快照、增量镜像、两套撤销历史同时引入会增加失步状态；现有 TextSession 使用完整文本历史 | 首版编辑历史由 Monaco 管理，Rust 在打开/保存/显式重比边界持有快照；增量协议仅在实测需要时增加。FND-02 |
| 架构 | P0 | 编辑器换行规范化与原文件字节保真不同；LoadedDocument::is_dirty 仅比较正文，save_document 正文未变即返回 | 分开磁盘格式与待保存目标格式，dirty/回执覆盖完整输出状态；混合换行未验证前只读。FND-02、FND-04 |
| 架构 | P1 | 同一文件可经不同路径或会话打开；调度若早于统一身份会产生依赖倒置 | FND-01 先定义文档身份与稳定写入键，FND-06 消费，FND-02 绑定编辑状态；SES-01 扩展视图，不另建身份体系 |
| 工程 | P0 | 配置位于可执行文件旁，见 compare-app 的 default_state_path，不适合安装目录 | 配置迁至平台应用数据目录，旧配置只读迁移并保留，损坏/未来版本不得覆盖。FND-05 |
| 工程 | P0 | 当前复制不承诺保留 ACL/ADS/xattr/硬链接语义，检查与提交仍有竞争窗口 | 明确普通文件支持边界；特殊类型拒绝或只读；不能宣称无竞争或整批事务。OPS-01、OPS-02 |
| 工程 | P1 | 单个 latest-request-wins worker 与多会话、写入任务的生命周期不完全适配 | 读任务可过期丢弃；写任务完成报告必须送达，取消按提交边界处理。FND-06 |
| 工程 | P1 | 当前目录比较返回完整报告，进度计数不等于渐进结果；文本性能仅有稀疏变化 CLI 数据 | 分批目录状态、错误聚合、UI/内存/病理输入基准分别验收。DIR-01、VAL-02 |
| 产品 | P0 | 打包、安装、升级、卸载与配置保留未形成闭环，资源发现不能拖到发布前 | FND-00 登记暂定范围、三目标环境/负责人/签名缺口；REL-01 最终验证支持矩阵，REL-02 验证升级。构建不等于正式支持 |
| 产品 | P1 | 差异检查、方向性复制、同步、三方合并的成功标准混杂 | 区分读取、编辑、写入和冲突处理流程，删除型同步后置。product.md 功能表、OPS-03、GIT-02 |
| 产品 | P1 | 原型功能存在与新桌面可交付状态混用 | 原型基线、文档交付、新产品节点分账；新节点未验收保持未勾选。plan.md 状态规则 |
| 产品 | P1 | 未保存退出、外部修改、崩溃恢复、日志隐私与错误补救缺少明确边界 | 首版提供关闭保护和外部修改处理；可选恢复草稿分节点实施。TXT-03、SES-03、REL-03 |
| 协作 | P1 | 多人修改 DTO、锁文件、主题和任务状态容易冲突 | 稳定任务 ID、短周期契约冻结、文件范围交接、单一事实来源、仓库级 skill。DOC-03、FND-01 |
| 协作 | P1 | 仅靠文字规范无法保证 AI 或贡献者遵守 | 根 AGENTS 提供入口，skill 执行流程，文档检查器提供最低校验，完整 CI 门禁待实施。DOC-04、FND-07 |

P0 表示进入可写或发布阶段前必须解决；P1 表示对应功能交付前解决，并非要求所有问题在基础骨架阶段一次实现。

## 六项规划决策

下列结论已落实到 [架构](architecture.md)、[任务计划](plan.md) 和各自验收条件；它们表示规划问题已处理，不表示技术能力已实现。任务完成状态只维护在 plan.md，所有目标功能节点保持未完成。

| 议题 | 已有覆盖与实际缺口 | 最终决策及对应任务 |
| --- | --- | --- |
| 仅格式保存 | 架构“文档状态与保存协议”已有保存期间正文保护；缺目标格式基线及仅格式保存。现有 fs 源码确有正文相同提前返回限制 | Rust 管磁盘格式，前端文档控制器管目标格式；dirty 比较正文与格式，回执只确认捕获快照。FND-02 验状态协议，FND-04 验 BOM/GBK/换行真实输出与失败保留，VAL-01 回归 |
| 复制期间编辑 | 架构“文件系统与目录模型”、OPS-01 已拒绝初始脏目标；缺执行期间与重开的保护 | 执行前预留整批键并确认所有目标冻结；执行中禁变更，重开延后加载；回执条件不符不重载，终态统一解冻。OPS-01、OPS-02、VAL-01 |
| 实例与 Git 等待 | 原方案有单主窗口和 GIT-01 等待要求；没有明确进程、会话及临时输入寿命关系 | FND-00 固定普通桌面单实例、每次 difftool 独立只读进程；FND-01 定义会话/终态，GIT-01 等明确完成及进程退出，验证 dirty 窗口、连续调用、临时输入与取消 |
| 身份与调度顺序 | 原 FND-06 按文档串行，但身份归在后置 FND-02 | 将最小注册表与协调键移入 FND-01，随后 FND-06，再由 FND-02/FND-04 接入状态与写入。保留 ID，不增加通用调度框架 |
| M0 编辑器门槛 | 架构已要求本地 worker/CSP 和降级，quality.md 已要求 M0 预算，但 FND-03 未承接完整验收 | FND-03 纳入最小中文 IME、实际 CSP 离线 Release/worker、超长行/密集差异和编辑/内存/启动初步预算；UX-02 保留完整无障碍，VAL-02 做完整性能验证修订 |
| 发布资源与最低版本 | release.md 已要求 REL-01 实测最低版本；架构曾将最小 OS 放在 M0 定案，时间点冲突 | FND-00 调查暂定范围、环境/负责人/签名资源，未知项明示；REL-01 最终验证并公布。三目标标准保留，资源不足仅标内部测试包，不算正式支持 |

源码限制依据：[compare-fs 文档模型与保存实现](../../crates/compare-fs/src/lib.rs)。LoadedDocument 与 save_document 的完整格式保存协议仍待 FND-02、FND-04 实现。

## 已有资产与证据边界

- 文本、编码、复制、会话及 CLI 已有源码和测试，见 [plan.md 的 BASE 节点](plan.md)。
- [validation.md](validation.md) 记录了原型的 32 项自动测试及部分 Windows 窗口验证；不是 Tauri、macOS 或安装包验证。
- 本地当前未发现可执行的 Cargo 或仓库隔离 Rust 工具链，原型测试未重新执行。实现盘点与历史验证分开记录。
- 尚未建立 Tauri 应用、前端依赖、双平台 CI、签名和发布流水线。
- 上述问题通过规范与任务拆解得到定位；未实现的技术能力仍保持待开发。

## 技术决策边界

- 不以 AI 编码速度推导工期；按可复现验收结果推进。
- 不先拆出插件宿主、数据库、网络服务或自研编辑器。
- Monaco 的可用扩展能力和规则兼容性是首轮技术门槛，不预设私有 API 可以长期维护。
- FND-00 记录暂定最低系统/WebView 与发布资源；REL-01 凭真实证据确定正式支持，签名资源不足不降低门槛。三方合并库在 GIT-02 评估。需要外部资源的操作不由普通开发授权自动覆盖。
